# Plan Review Log: SleepAgent 产品信息架构与核心页面主线
Act 1 (grill) complete — plan locked with the user. MAX_ROUNDS=5.

## Round 1 — Codex review

1. **“记录”仍可能成为杂物页。** 页面同时承载睡眠、报告、照护、设备和技术详情，却没有固定二级入口；修复：锁定“睡眠记录、我的报告、照护记录、设备与数据质量”四个二级分组，并以睡眠记录为默认。
2. **照护行动的管理入口不唯一。** 手动测试允许在“今天或Chat”停止行动，会造成两个页面都像正式管理页；修复：对话页是唯一正式管理入口，今天只展示和跳转。
3. **跨页面Chat上下文不可见。** 自动携带上下文若不显示，老人无法判断回答依据昨夜还是近30天；修复：对话顶部持续显示可切换的依据范围。
4. **开发入口可能泄漏到老人信息层。** “记录—技术详情入口”与独立工作台边界不够严格；修复：老人只看易懂来源摘要，完整工作台入口仅在获授权内部环境或开发身份下出现。

VERDICT: REVISE

### Codex response

接受四项发现并修订。修改只消除页面归属歧义，没有增加新页面，也没有改变已锁定的四入口结构或三身份模式。

## Round 2 — Codex review

1. **非首页页面缺少空状态。** 趋势、对话和记录都默认数据与服务可用，真实情况下可能出现空图表、伪个性化或死路；修复：分别增加数据不足、首次使用、无历史和暂不可用状态。
2. **Chat不可用时可能拖垮整个产品。** 对话是主力点，但晨间事实不应随模型故障消失；修复：Chat明确降为暂不可用，今天仍保留已生成事实且不要求创建任务。
3. **照护行动状态可能跨页漂移。** 计划要求四页一致，却没有统一状态词；修复：锁定待确认、进行中、已暂停、已完成、已结束五个产品状态。
4. **手动测试只覆盖理想状态。** 缺少少量历史和Chat不可用场景；修复：增加两个失败路径测试。

VERDICT: REVISE

### Codex response

接受四项发现。新增的是页面状态与统一文案契约，不涉及服务降级机制、数据库或模型实现。

## Round 3 — Codex review

1. **“复用现有组件”可能把旧产品语义带回主线。** 多个旧页面仍绑定 SHHS／PSG、AHI、mock 病人与单任务上下文；修复：区分可复用的 radar 产品能力与只能借鉴的交互模式，禁止旧字段成为新产品默认内容。
2. **重新启用旧固定工作区不是安全的捷径。** `LegacyFixedRadarWorkspace` 虽有三角色和自动结果，但仍是固定 replay 任务；修复：只借鉴内容分层，不能整体恢复为产品主入口。
3. **报告归入记录可能意外扩大访问权。** 页面树列出三类报告，但信息架构不能代替授权；修复：当前身份只看原本有权材料，现有确认和授权边界保持不变。
4. **本轮可能被误读为同时重做三种身份页面。** 用户已锁定三身份模式；修复：明确本计划只定义老人第一入口，家属／医生信息架构另立后续主题才可调整。

VERDICT: REVISE

### Codex response

接受四项发现。修订强化了“在已有基础上复用”的边界：保留真实能力与已验证模式，不复活旧主线，也不改变三身份授权。

## Round 4 — Codex review

1. 四个一级入口均有唯一职责，记录页也已用固定二级分组避免退化为杂物页。
2. 今天、趋势、对话和记录之间的上下文、照护行动所有权与统一状态已明确。
3. 完成、数据不足、首次使用、无历史、服务不可用和急症等非理想状态均有产品路径，不再回退到任务启动器。
4. 现有 radar 能力、旧交互模式、固定 replay 工作区与动态开发工作台的复用边界已清楚，不会把 PSG／mock 主线重新带回产品。
5. 三身份与授权保持不变，本轮没有越界重做家属或医生信息架构。

VERDICT: APPROVED
